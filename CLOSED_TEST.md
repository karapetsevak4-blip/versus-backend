# Закрытый тестовый режим

Для будущего стенда использовать `DJANGO_SETTINGS_MODULE=mysite.settings_staging`.
Это отдельный профиль PostgreSQL; `settings_test` предназначен только для
автоматических офлайн-тестов. Compose приложения ещё не подготовлен.

Обязательные переменные:

- `TELEGRAM_TESTER_IDS`: положительные Telegram ID через запятую, без username.
- `TELEGRAM_TEST_BOT_ID`: ID отдельного тестового бота.
- `SECRET_KEY_FILE`, `TELEGRAM_TOKEN_FILE`, `POSTGRES_PASSWORD_FILE`: пути к
  смонтированным файлам секретов. Также поддерживаются переменные без `_FILE`.
  Не передавать токен/пароль в аргументах команд или в исходниках.
- Для команды /start понадобится `FRONT_URL=https://test.versuschain.com`.

В профиле постоянно включён `CLOSED_TEST_MODE`. Его нельзя выключить через env.
Пустой список тестеров или отсутствие секретов блокирует загрузку профиля.
Подпись Telegram по-прежнему обязательна; список тестеров проверяется после
подписи и на каждом защищённом API-запросе. Удаление ID отзывает существующую
сессию при следующем запросе.

В режиме заблокированы invoice (API и функция бота), положительный pre-checkout,
обработка successful_payment, refund, денежные реферальные начисления,
распределение сезонного приза и изменение адреса кошелька. Полученный платёжный
event только регистрирует ошибку без личных данных и изменения баланса;
это не процедура возврата реально списанных средств.

До polling бот проверяет свой ID и наличие webhook. Настроенный webhook
останавливает запуск; автоматического удаления webhook/очереди больше нет.
Транспорт бота пока обычный: curl-туннель на сервере не подключается к aiogram
автоматически. Polling до подготовки транспорта не запускать.

Staging URL configuration исключает admin и Swagger. Health endpoint проверяет
только живой процесс. HTTPS cookies имеют отдельные имена и не задают общий
домен. Reverse proxy должен перезаписывать X-Forwarded-Proto, а backend порт
должен оставаться недоступным из интернета. Профиль сам по себе не заменяет
настройку proxy, firewall и TLS.

Фронтенд собирать с `VITE_CLOSED_TEST_MODE=true`: TonConnectUI не создаётся,
нажатие кошелька показывает сообщение об отключении. Серверный запрет
продолжает действовать независимо от frontend-флага.

Проверки: `python manage.py test --settings=mysite.settings_test`.
Новые тесты используют искусственные ID, поддельный токен и mock Telegram.
Реальный Telegram-вход, PostgreSQL-интеграция приложения, гонки регистрации,
стартовые данные, UI и HTTPS проверяются отдельно. Полной атомарности создания
игрока пока нет; отсутствие стартового офиса/трейдера возвращает 503 до создания.

До внешнего доступа отдельно устранить устаревшие зависимости: официальная
документация Django отмечает ветку 5.1 как неподдерживаемую. Требуется проверяемое
обновление, а не открытие старой версии в интернет.

## Начальный тестовый баланс

Владелец согласовал 10 000 Coins и 1 000 внутренних тестовых единиц для своего
первого тестового аккаунта. Указать его ID через FUNDED_TESTER_ID; он обязан
входить в TELEGRAM_TESTER_IDS. Деньги выдаются только при создании UserBalance
в закрытом режиме. Повторный вход, остальные тестеры и обычный режим ничего
не начисляют. Существующий аккаунт автоматически не пополняется.

Существующий purchase-код использует название currency=stars для token_money.
Это историческое имя внутреннего маршрута баланса, не реальный Stars-платёж
и не конверсия USD в Stars. Тестовые средства не пополняют призовой фонд или
платёжные Transaction. Не загружать полный каталог v0.4 до поддержки
дробной цены L2 и unlimited/dynamic safe Tower.
